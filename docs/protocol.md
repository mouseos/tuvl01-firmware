# TUVL01 Wi-Fi プロトコル（クライアント非依存）

TVTest、スマートフォン、その他どのクライアントからでも使える、TUVL01 の Wi-Fi 制御・ストリーム仕様です。
ファームウェアは特定のプレーヤーやOSを前提にしません。クライアント側の実装（BonDriver、Android 等）がこの仕様だけに依存します。

## ネットワーク

| 項目 | 値 |
| --- | --- |
| AP | open SSID `TUVL01`、2.4GHz、単一クライアント |
| 装置 IP | `192.168.74.1`（DHCP 固定割当、クライアントは `192.168.74.2`） |
| 制御 | UDP `192.168.74.1:4200`（要求/応答） |
| 生存確認・エコー | UDP `192.168.74.1:4201`（受けた内容をそのまま返す。任意の1バイト以上） |
| ストリーム | UDP 装置 `:4202` → クライアント `192.168.74.2:4202` |

数値はすべてビッグエンディアンです。クライアントは `192.168.74.2:4202` を bind して受信します。

## ストリーム（TTS1）

1 データグラムは 16 バイトのヘッダと、188 バイト TS パケットを 1 個以上（最大 7 個）並べた本体です。

| オフセット | 長さ | 内容 |
| --- | --- | --- |
| 0 | 4 | `TTS1` |
| 4 | 4 | シーケンス番号（データグラム毎に +1、32bit で巻く） |
| 8 | 4 | 先頭 TS パケットの通し番号（パケット毎に加算） |
| 12 | 4 | フラグ。bit0 = 装置 FIFO の再同期が起きた。それ以外は 0 |
| 16 | 188×n | TS パケット |

欠落はシーケンス番号の飛びで検出できます。本体は変更せずそのまま TS として扱えます。

## 制御（UDP 4200）

要求は 8 バイトのヘッダと、操作ごとのペイロードです。

| オフセット | 長さ | 内容 |
| --- | --- | --- |
| 0 | 4 | `TCT1` |
| 4 | 1 | 操作コード |
| 5 | 1 | 予約（0） |
| 6 | 2 | 要求 ID（応答にそのまま返る） |

応答は同じ形式で、操作コードの最上位ビットが立ち（`op|0x80`）、オフセット 5 が状態になります。
状態: `0` 成功、`1` 要求不正、`2` 未対応の操作。マジックが違う要求と短すぎる要求は応答しません。

| 操作 | コード | 要求ペイロード | 応答ペイロード |
| --- | --- | --- | --- |
| HELLO | 1 | なし | プロトコル版 u8、ファームウェア revision u16、機能ビット u32、ストリームポート u16、状態 u8、最初のチャンネル u8、最後のチャンネル u8 |
| START | 2 | なし | 状態 u8 |
| STOP | 3 | なし | 状態 u8 |
| STATUS | 4 | なし | 状態 u8、チャンネル u16（0 = 未選局）、モード u8、選局状態 u8、ロック u8 |
| KEEPALIVE | 5 | なし | 状態 u8 |
| TUNE | 6 | チャンネル u8（13..52）、モード u8（0 = フルセグ、1 = ワンセグ） | 選局状態 u8 |

ストリーム状態: `0` 停止、`1` 送信中、`2` 開始要求を受理済み（まもなく送信）。

機能ビット: bit0 = START/STOP 対応、bit1 = TUNE 対応（UHF 13..52ch）。

選局状態: `0` 未実施、`1` 選局中、`2` 完了、`3` 失敗。
ロック: `0` 非ロック、`1` フレーム同期ロック、`255` 不明（選局直後や未取得）。約 1 秒ごとに更新されます。

### 動作

- `START` は要求の送信元ではなく、装置が固定で持つクライアント `192.168.74.2:4202` へ送ります。送信中の `START` は何もせず成功します。
- `START` を受理しても、チューナーが未準備なら送信は始まりません。クライアントは `STATUS` で状態が `1` になることを確認してください。
- 制御で開始したストリームは、**クライアントから 4200 または 4201 宛てのデータグラムが 5 秒間なにも来ない**と、装置が自動で停止します（クライアントが落ちても送信し続けないため）。
  生存確認には `KEEPALIVE` を 1 秒間隔程度で送るか、省電力対策の上り 4201 パケット（下記）を使います。
- UART から開始したストリームは自動停止しません。
- `TUNE` は走行中のストリームを停止してから選局します。STATUS の選局状態が `2`（かつチャンネル・モードが要求どおり）になるまで待ち、その後に `START` を送ってください。選局には通常 1 秒前後、最長で数秒かかります。選局中も制御は応答します。
- 選局が失敗（状態 `3`）しても、直前のチャンネルは STATUS に残ります。範囲外のチャンネル・モードは状態 `1`（要求不正）で拒否します。
- 選局の完了はチューナー設定の完了であり、放送の受信を保証しません。受信できているかは STATUS のロックで確認します。

### 省電力対策

PC の Wi-Fi アダプタが省電力に入ると、装置のフレームが落ちる場合があります。
ストリーム中に 4201 へ短いデータグラムを 10ms 間隔程度で送ると、欠落が減ります（装置はエコーを返します）。
